# LLM 실전 기본기

## 이 장에서 꼭 가져갈 한 문장

LLM을 잘 다루려면 모델 구조만 아는 것으로는 부족하고, 토큰, 컨텍스트, 샘플링, 평가를 함께 이해해야 한다.

## 왜 이 장이 필요한가

GPT-3를 이해했다고 해서 바로 실전 감각이 생기지는 않는다. 실제로는 컨텍스트 윈도우, temperature, top-k, top-p, 프롬프트 구조, 평가 기준 같은 요소들이 결과 품질을 크게 바꾼다.

## 실전 제어판

<MermaidDiagram>
flowchart LR

## 1차 패스에서 볼 것

- 토큰과 컨텍스트 윈도우
- temperature, top-k, top-p
- 프롬프트 구조화의 기본
- 평가와 hallucination의 기초

## 핵심 표

| 요소 | 왜 중요한가 |
| --- | --- |
| 토큰 길이 | 비용과 입력 한계를 결정한다 |
| 컨텍스트 윈도우 | 얼마나 많은 정보를 한 번에 참고할지 결정한다 |
| 샘플링 파라미터 | 출력의 안정성과 다양성을 바꾼다 |
| 평가 기준 | "좋다"를 감이 아니라 지표와 관찰로 바꾸어 준다 |

## 샘플링 파라미터 빠르게 보기

| 파라미터 | 보통 어떤 효과가 있는가 |
| --- | --- |
| temperature | 높을수록 더 다양한 출력을 만들기 쉽다 |
| top-k | 상위 k개 후보 안에서만 고르게 한다 |
| top-p | 누적 확률이 p가 될 때까지의 후보 안에서 고르게 한다 |

## 프롬프트 기본 패턴

- 역할을 먼저 분명히 지정한다
- 입력 데이터와 제약 조건을 분리해 쓴다
- 원하는 출력 형식을 명시한다
- 평가 기준이 있다면 프롬프트 바깥에서도 같이 관리한다

## 평가를 왜 따로 해야 하는가

좋아 보이는 샘플 몇 개만으로는 시스템 품질을 판단하기 어렵다. 최소한 아래 셋은 분리해서 생각해야 한다.

- 정확도나 성공률 같은 task-level 성능
- 사람이 읽었을 때의 품질
- 비용, latency, 실패 패턴

## 연습

1. temperature와 top-p가 각각 무엇을 조절하는지 설명해본다.
2. 긴 컨텍스트가 항상 좋은 것은 아닌 이유를 적어본다.
3. "프롬프트를 잘 썼다"를 평가로 바꾸려면 무엇이 더 필요한지 적어본다.

## 체크리스트

- 토큰 길이가 비용과 성능에 어떤 영향을 주는지 설명할 수 있는가
- temperature가 출력을 어떻게 바꾸는지 설명할 수 있는가
- hallucination을 줄이기 위해 무엇을 점검해야 하는지 말할 수 있는가
