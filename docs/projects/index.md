# 프로젝트

## 이 장에서 꼭 가져갈 한 문장

좋은 프로젝트는 코드가 돌아가는 것만이 아니라, 설계 이유와 평가 방식과 운영 리스크까지 설명할 수 있어야 한다.

## 제안 프로젝트

1. 문자 단위 또는 작은 토크나이저 기반 언어 모델
2. 문서 QA 또는 미니 RAG 앱
3. bandit 또는 간단한 RL 실험

## 프로젝트 템플릿

- 문제 정의
- 데이터와 제약
- 모델 또는 시스템 설계
- 구현
- 평가
- 회고

## 포트폴리오 관점

프로젝트는 "돌아간다"에서 끝나면 약하다. 왜 그런 설계를 했는지, 어떤 지표로 평가했는지, 운영상 어떤 리스크가 있었는지까지 남겨야 포트폴리오가 된다.

## 체크리스트

- 문제 정의가 분명한가
- 평가 기준이 있는가
- 회고에서 개선 포인트를 말할 수 있는가

## 다음 장으로 어떻게 연결되는가

프로젝트 장은 끝이 아니라 다시 시작점이다. 프로젝트를 만든 뒤에는 수학, Transformer, AI Engineering 섹션으로 돌아가 약한 부분을 다시 채운다.
